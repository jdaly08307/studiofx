1Data Flow Directions

Two directions: inbound pull and outbound action

DirectionWhat it meansExamples
Inbound (pull) ThreatAware calls the source tool's API to read data CrowdStrike → ThreatAware, Lansweeper → ThreatAware, Intune → ThreatAware
Outbound (action) ThreatAware sends data or triggers actions in another tool ThreatAware → Autotask (create ticket), ThreatAware → ServiceNow (raise incident)

The vast majority of integrations are inbound pulls. ThreatAware is the consumer of your tools' APIs, not the publisher. Outbound actions are mostly limited to ticketing and workflow tools.

Authentication

ThreatAware supports the auth patterns used by SaaS security tools:

  • API key — most common; the customer generates a read-only key in the source tool and pastes it into ThreatAware
  • OAuth / client credentials — used by Microsoft Intune, Azure AD / Entra ID
  • Username + password — some legacy tools
💡
Talking point for engineers

ThreatAware recommends a dedicated read-only service account or API key with minimum required permissions in each source tool. It never needs write access to those tools to function — a common concern engineers raise first.

What gets pulled

Regardless of source tool, ThreatAware is always looking for the same core entities:

EntityFields pulled
Devices / endpointsName, OS, last seen, IP, MAC, serial, coverage state
UsersIdentity, associated devices, groups
AlertsThreat detections, severity, status, affected asset
Patch / vuln dataCVEs present, last patch date, missing patches

A typical use case: a SOC team writes a script calling ThreatAware's /devices endpoint to pull a clean, deduplicated asset list into their SIEM — because ThreatAware has already done the correlation work.

Common engineering questions — answered

QuestionHonest answer
"Is there a webhook / real-time push?" The API is poll-based (read). Real-time alerting happens within the ThreatAware UI and via connected ticketing tools. Confirm webhook support directly with ThreatAware's technical team.
"Can I write back to ThreatAware via API?" The current public API is read-only. Actions (like creating tickets) are handled through outbound tool integrations configured in the platform.
"How often is data refreshed?" ThreatAware polls each source on a schedule — cadence varies by integration type. Some tools have near-real-time connectors; others are hourly or daily. Confirm per-integration with ThreatAware.
"What about data residency / GDPR?" Flag to ThreatAware's technical team — this is a deal-stage question, not a pre-sales blocker to resolve alone.
