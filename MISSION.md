# Mission: ThreatAware — Architecture, API & Interface

## Why
Gain enough technical fluency with ThreatAware to present the platform credibly to prospects and hold a surface-level architectural conversation with engineers. The goal is confident explanation, not deep implementation knowledge.

## Success looks like
- Can explain what CAASM is and why ThreatAware's approach is distinctive (timeline matching, agentless)
- Can describe the data flow: how tools feed ThreatAware, how it correlates and enriches, what comes out
- Can answer an engineer's first-round questions about the API model (REST, read vs write, auth, data entities)
- Can walk a prospect through the software interface — dashboard, X-Ray view, query language, reporting
- Can hold a whiteboard-level architecture conversation without notes

## Constraints
- Not a ThreatAware engineer — depth of understanding is "explain and demo", not "implement and configure"
- Need to be accurate enough that an engineer doesn't immediately dismiss the explanation
- Time is limited — needs to be learnable across a few sessions

## Out of scope
- Deep API development (writing clients, handling pagination, error handling)
- Internal ThreatAware infrastructure / backend implementation
- Competing CAASM platforms (for now)
