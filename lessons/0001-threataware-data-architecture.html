1The Problem

Why organisations can't see their own estate

Most organisations run 10–30 security and IT tools — an EDR, a patch manager, an MDM, a vulnerability scanner, a SIEM. Each tool sees a different slice of the environment. None of them agree on what's actually out there.

💬
The core pitch

ThreatAware answers one question: "Do I have complete, accurate visibility of every asset, and do I know exactly which security controls are working on each one?" If the prospect can't answer that confidently today, ThreatAware is the answer.

ThreatAware belongs to the CAASM category — Cyber Asset Attack Surface Management — a Gartner-defined market for tools that aggregate asset data across security tools via API and correlate it into a single view.

2Data Architecture

The four-layer pipeline

L1
Sources — your existing tools

ThreatAware pulls from tools already deployed: CrowdStrike, Intune, Lansweeper, Qualys, Active Directory. It is agentless — nothing is installed on endpoints. Connection is API-to-API only.

L2
Ingest

Each integration uses an API key or OAuth credential from the source. ThreatAware polls on a schedule, pulling raw records: device names, IPs, OS versions, patch status, user associations, alerts. Raw data is stored per-source and fully auditable.

L3
Correlation & Enrichment — the secret sauce

A laptop might be JSMITH-WIN11 in CrowdStrike, 192.168.1.54 in Qualys, and John Smith's MacBook in Jamf. ThreatAware's timeline matching technology resolves these into a single canonical asset record, cross-referencing hostname, IP, MAC address, serial number, user, and timing signals.

L4
Unified Asset Intelligence Store

One record per asset: device identity, OS, owner, which tools cover it, patch status, CVEs, control gaps, alert history. This store powers dashboards, the query language, the API, and automated alerting.
