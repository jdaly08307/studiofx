Walking Through the ThreatAware Interface

This lesson maps the ThreatAware UI so you can walk a prospect through it — or describe what they'll see — with confidence. Each section corresponds to a distinct area of the product.

1. The Interface at a Glance

ThreatAware's interface is organised around five primary areas:

#AreaWhat it answers
1Main Dashboard"What is my security posture right now, and what's changing?"
2Asset Inventory"What devices, users, and software are in my estate?"
3X-Ray View"What raw data did each individual tool send, and does it match?"
4Query Language"Let me find every device where Defender is missing AND patch is overdue."
5Custom Dashboards & Reporting"Give me a weekly executive report and a SOC dashboard, automatically."

2. Main Dashboard

The dashboard is the first screen after login. Think of it as the health monitor of the entire IT estate.

Key elements:

  • Trend data — charts showing how posture metrics are moving over time (devices covered by EDR this week vs. last week)
  • Risk priorities — surfaced issues ranked by severity: unprotected devices, missing patches, critical alerts
  • Action items — specific things that need to be addressed, with drill-down capability
  • Integration health indicators — are all your source tools connected and syncing?
Demo talking point
"The dashboard becomes the single pane of glass that replaces tabbing between 12 different tools. Your team wakes up here every morning. If something's red, they know immediately — and they can click straight to the affected device."

3. Asset Inventory

This is the heart of what ThreatAware delivers: a complete, correlated device, user, and software inventory.

Each asset record shows:

  • Device identity (name, OS, hardware)
  • Last seen / active status
  • Which integrations "see" this device (and which don't — the gap)
  • Control coverage: EDR installed? Patch current? Encryption enabled?
  • User association
  • Open vulnerabilities / CVEs
  • Alert history
The "stealth device" moment
When demoing, filtering to show devices that appear in only one integration (or none of the expected ones) is a powerful moment. These are the blind spots — real devices with no EDR, no patch management, fully exposed. Most prospects immediately recognise some of them.

The inventory is described by ThreatAware as "the replacement for the traditional asset spreadsheet." That framing resonates with buyers who've been managing Excel sheets or out-of-date CMDBs.

4. X-Ray View

The X-Ray View is a transparency layer — it shows the raw, per-source data before correlation. This is where engineers spend time to verify accuracy and audit the platform's work.

Why it matters:

  • Engineers can see exactly what data CrowdStrike, for example, sent for a specific device
  • They can validate that ThreatAware's correlation is correct ("yes, these two records are the same device")
  • It builds trust — nothing is hidden or black-boxed
  • Useful for compliance: you can prove where data came from
Common prospect concern
Engineers often ask: "How do I know the correlation is correct? What if it wrongly merges two devices?" X-Ray View is the answer. Show them the raw source data and the matched fields. ThreatAware's transparency here is a genuine differentiator.

5. The Query Language

ThreatAware includes a powerful query language for filtering and searching across the unified asset data. This is where power users live.

Example queries you can describe to a prospect:

# All devices missing EDR coverage
device.edr_installed = false

# All devices last seen more than 30 days ago
device.last_seen > 30d

# Devices with critical CVEs where patch is not current
device.cve_severity = "critical" AND device.patch_status != "current"

# Devices assigned to a user in the Finance department
device.user.department = "Finance" AND device.os = "Windows"

(Note: the exact syntax lives in the platform. The above illustrates the capability — boolean logic, field filtering, cross-entity queries.)

Saved queries become custom views that can be shared with stakeholders — a SOC analyst's view looks different from a CISO's view.

6. Custom Dashboards & Automated Reporting

Beyond the main dashboard, ThreatAware lets users build tailored dashboards for different audiences:

  • Executive / CISO dashboard — high-level posture score, trend, compliance readiness
  • SOC dashboard — active alerts, unresolved risk, coverage gaps by team
  • Compliance dashboard — control mapping to frameworks (Cyber Essentials, ISO 27001, etc.)
  • Team-specific views — share a filtered view with the network team vs. the endpoint team

Automated reports can be scheduled and emailed — weekly posture summaries, monthly board-level reports — without manual effort each cycle.

Sales talking point
"The CISO can get a board-ready PDF every Monday morning automatically. The SOC gets their live view in the platform. Neither has to ask the other for data."

7. The Demo Walk — A Suggested Sequence

When walking a prospect through ThreatAware, use this sequence. It builds from big picture to technical depth:

  1. Dashboard first — "This is what your team sees every morning."
  2. Asset inventory — "Here's every device, correlated from all your tools."
  3. Filter to gaps — "Watch what happens when I filter to devices missing EDR…" (the moment of impact)
  4. Drill into a device — "Click any device and you see every tool that sees it — and every tool that doesn't."
  5. X-Ray View — "If you want to see the raw source data behind any record, here it is."
  6. Query language — "Your SOC can write queries like this to build any custom view they need."
  7. Reporting — "And this goes to your CISO automatically every week."
