What ThreatAware Is and How Data Flows Through It

By the end of this lesson you'll be able to explain ThreatAware's architecture in a single whiteboard conversation — what it does, why organisations buy it, and exactly how data moves from their existing security tools into a unified view.

1. The Problem ThreatAware Solves

Most organisations have 10–30 security and IT tools — an EDR, a patch management tool, an MDM, a vulnerability scanner, a SIEM. Each tool sees a slice of the environment. None of them agree on what's actually in the estate.

The result: blind spots. On average, organisations don't know about roughly 30% of the devices on their network. Those unknown devices are unpatched, unmonitored, and wide open.

The core pitch
ThreatAware answers one question: "Do I have complete, accurate visibility of every asset, and do I know exactly which security controls are working on each one?" If the prospect can't answer that confidently today, ThreatAware is the solution.

ThreatAware is a Cyber Asset Attack Surface Management (CAASM) platform. CAASM is an analyst category (coined by Gartner) for tools that aggregate asset data across security tools via API, then correlate it into a single view. ThreatAware is one of the leading dedicated CAASM vendors.

Layer 1 — Sources (your existing tools)

ThreatAware pulls data from the tools already deployed in an organisation. These are called integrations. Examples include:

  • Endpoint detection & response (EDR) — CrowdStrike, SentinelOne, Defender
  • Patch management — Action1, Automox, Ivanti
  • Mobile device management (MDM) — Intune, Jamf
  • Asset discovery — Lansweeper, Nmap-class tools
  • Vulnerability scanners — Qualys, Tenable
  • Identity / directory — Active Directory, Azure AD
  • Ticketing / ITSM — Autotask, ServiceNow (for outbound actions)

ThreatAware is agentless — nothing is installed on end devices. The connection is purely API-to-API: ThreatAware calls each tool's API to pull data.

Layer 2 — Ingest

Each integration is configured with an API key or OAuth credential from the source tool. ThreatAware polls each source on a schedule, pulling raw records: device names, IP addresses, OS versions, patch status, user associations, alert data. This raw data is stored per-source and is fully visible in the X-Ray View (covered in Lesson 3).

Layer 3 — Correlation & Enrichment (the secret sauce)

This is where ThreatAware's distinctive value lives. The platform uses timeline matching technology to resolve the same physical device appearing under different names across different tools. A laptop might be called JSMITH-WIN11 in the EDR, 192.168.1.54 in the vulnerability scanner, and John Smith's MacBook in Jamf.

ThreatAware matches on combinations of: hostname, IP address, MAC address, serial number, user association, and temporal signals (did these records appear at the same time on the network?). It resolves them into a single canonical asset record.

Why this matters in a sales conversation
The 30% of devices organisations don't know about aren't new devices — they're devices that exist in one tool but not another, so they fall through the gap. Timeline matching surfaces them. That's the "aha" moment for most prospects.

Layer 4 — Unified Asset Intelligence Store

After correlation, ThreatAware maintains a single record per asset that includes:

EntityWhat it captures
DevicesHostname, OS, owner, network info, which tools cover it, patch status, CVEs, control gaps
UsersAssociated devices, identity sources, alert associations
AlertsCross-tool alert data, enriched with asset context
ControlsPer-device: is EDR installed? Is patching current? Are expected tools present?

This store is what powers the dashboards, the query language, the API, and the automated alerting.

3. The Deployment Story

A point worth knowing for sales: ThreatAware can be connected and returning value in under 30 minutes. There is no agent rollout, no professional services engagement to start, no firewall changes. You add an integration by entering an API key and pointing ThreatAware at the source tool's cloud API.

This is a strong differentiator against legacy asset management tools (CMDBs, spreadsheets, manual agents) that can take months to deploy.
