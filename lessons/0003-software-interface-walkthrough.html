3Asset Inventory

The replacement for the asset spreadsheet

The heart of what ThreatAware delivers: a complete, correlated device, user, and software inventory — assembled from every source tool, deduplicated.

Each asset record shows:

  • Device identity — name, OS, hardware
  • Last seen / active status
  • Which integrations "see" this device (and which don't — the gap)
  • Control coverage: EDR installed? Patch current? Encryption enabled?
  • User association
  • Open vulnerabilities / CVEs
  • Alert history
🎯
The "stealth device" demo moment

Filter to devices that appear in only one integration — or none of the expected ones. These are real machines on the network with no EDR, no patch management, fully exposed. Most prospects immediately recognise some of them. This is the moment the product sells itself.

4X-Ray View

Raw source data — the trust layer

The X-Ray View is a transparency layer — it shows the raw, per-source data before correlation. This is where engineers spend time to verify accuracy and audit the platform's work.

What X-Ray lets you doWhy it matters
See exactly what CrowdStrike sent for a specific deviceVerify the source data is complete and accurate
Validate correlation decisions"Yes, these two records are the same device" — build trust with engineers
Trace the provenance of any fieldNothing is black-boxed; every data point has a source
Support compliance auditsProve where data came from and when it was ingested
⚠️
Common engineering concern — addressed by X-Ray

"How do I know the correlation is correct? What if it wrongly merges two devices?" X-Ray View is the answer. Show them the raw source data and the matched fields side by side. This transparency is a genuine differentiator — most CAASM tools hide this.

5Query Language

Power-user filtering across the entire estate

ThreatAware includes a powerful query language for filtering across the unified asset data. Example queries you can describe to a prospect:

# All devices missing EDR coverage
device.edr_installed = false

# Devices not seen in the last 30 days
device.last_seen > 30d

# Critical CVEs where patching is not current
device.cve_severity = "critical" AND device.patch_status != "current"

# Finance department devices running Windows
device.user.department = "Finance" AND device.os = "Windows"
💡
Note on syntax

The above illustrates the capability — boolean logic, field filtering, cross-entity queries. The exact syntax lives in the product. Don't recite syntax from memory; show the concept instead.

Saved queries become custom views that can be shared with stakeholders — a SOC analyst's view looks different from a CISO's, and neither has to build it from scratch each time.
